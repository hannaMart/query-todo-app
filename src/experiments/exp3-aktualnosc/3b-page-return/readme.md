## Цель эксперимента

Цель подэксперимента 3b — сравнить, как ручное управление server-state и React Query обеспечивают актуальность данных при повторном открытии страницы внутри приложения.

Проверяется, выполняется ли новый запрос после возврата пользователя на страницу в зависимости от возраста ранее полученных данных.

## Условия

В обоих вариантах используются одинаковые условия:

- единая база `TODOS`;
- одна функция `fakeFetchFreshness`;
- одинаковая искусственная задержка;
- порог актуальности — 60 секунд;
- фиксируются `requestId` и `fetchedAt`.

Изменяется только способ управления server-state.

## Manual

В ручной реализации самостоятельно создаются:

- кэш данных;
- время последнего получения данных;
- TTL = 60 секунд;
- проверка возраста данных при повторном монтировании компонента.

При возврате на страницу:

- если данные моложе 60 секунд — используется кэш;
- если данные старше 60 секунд — выполняется новый запрос.

## React Query

В React Query используется встроенный механизм:

```js
staleTime: 60_000;
```

React Query хранит данные в query cache и считает их свежими в течение 60 секунд.

При повторном открытии страницы:

- fresh data → новый запрос не выполняется;
- stale data → выполняется refetch.

## Сценарий проверки

### Возврат до 60 секунд

1. Открыть страницу 3b.
2. Зафиксировать `requestId` и `fetchedAt`.
3. Перейти на другую страницу приложения.
4. Вернуться раньше чем через 60 секунд.

Ожидаемый результат:

- нового запроса нет;
- `requestId` не изменяется;
- `fetchedAt` остаётся прежним.

### Возврат после 60 секунд

1. Снова покинуть страницу.
2. Вернуться после истечения 60 секунд.

Ожидаемый результат:

- выполняется новый запрос;
- `requestId` увеличивается;
- `fetchedAt` обновляется.

## Наблюдаемые параметры

Сравниваются:

- количество фактических запросов;
- значение `requestId`;
- время `fetchedAt`;
- использование сохранённых данных;
- объём логики, необходимой для реализации одинакового поведения.

## Вывод

Оба подхода позволяют избежать лишнего запроса при быстром возврате пользователя и выполнить обновление после истечения установленного времени актуальности.

Различие заключается в реализации механизма.

В manual-подходе разработчик самостоятельно создаёт кэш, хранит время получения данных и проверяет TTL.

В React Query аналогичное поведение задаётся через встроенную модель кэша и параметр `staleTime`.

Таким образом, подэксперимент показывает не различие конечного результата, а различие в способе и объёме управления актуальностью server-state.
